# Changelog

Notable changes to web-image-optimiser, newest first. A change to what the optimiser decides for the same input, such as a different format, method or quality after an engine update, is listed as an API change, and so is any change to the JSON contract's `schemaVersion`.

## Unreleased

Nothing released yet. Changes since work began:

- The `wio` command line (also `web-image-optimiser`): optimising with `--to`, `--target`, `--out-dir`, `--in-place`, `--overwrite`, `--recursive`, `--dry-run`, `--json`, `--ndjson` and `--concurrency`, and `wio compare`. Folders and glob patterns expand to their images, leaving out an earlier run's outputs. See `docs/cli.md`.
- `FileResult` has the image's `width` and `height`. A new `CompareResult`, which `wio compare --json` prints.
- The error codes `E_DIMENSIONS_MISMATCH` and `E_TOO_SMALL_TO_SCORE`, for comparisons, and the CLI's usage error code `E_NO_INPUTS`.
- An agent guide, `SKILL.md`, for a project to copy into its skills.
- PNG outputs try a palette PNG (at most 256 colours, as few as the quality allows) beside lossless PNG, in `same` mode for PNG inputs and for every suite fallback. It changed these decisions at target 80, the default then:
  - `same`, `screenshot.png`: a PNG strip of 47.7 kB became a palette PNG at quality 63, 11.6 kB.
  - `same`, `logo-alpha.png`: a PNG strip of 4.66 kB became a palette PNG at quality 1, 1.15 kB.
  - `same`, `text-chunks.png`: a lossless PNG of 119 kB became a palette PNG at quality 69, 29.8 kB.
  - `suite`, `screenshot.png`: the fallback went from a JPEG at quality 90 (27.8 kB) to a palette PNG (11.6 kB); the AVIF and WebP are unchanged.
  - `suite`, `logo-alpha.png`: the AVIF, WebP and PNG strip became one palette PNG of 1.15 kB, since the AVIF (1.61 kB) and WebP (2.23 kB) are now larger than the fallback and the chain rule drops them.
  - `suite`, `display-p3.jpg`: the fallback went from the JPEG's strip (6.50 kB, with `W_ICC_KEPT`) to a palette PNG at quality 50 (3.18 kB), without the warning.
  - `suite`, `lossless.webp`: a palette PNG of 1.21 kB became the fallback, where there was none, and the lossless WebP (2.81 kB), now larger than it, was dropped; the AVIF is unchanged.
- Batches run each lane in a child process rather than a worker thread, so each has its own pool of threads for sharp's work: 9 AVIF photos went from 270 s to 140 s on a 20-thread machine, with the same outputs. A crash inside sharp's native code now fails only that file, with `E_INTERNAL`.
- `wio` is an application, a CLI and a desktop app, not a library: `package.json` is private, so nothing is published to npm, and there is no importable API and no JSON Schema files. Install it from a clone with `npm link`.
- Lossless WebP compresses as hard as libwebp can (quality 100, which lossless mode reads as effort, where sharp defaults to 80), with the same pixels. It changed these decisions at target 80, the default then:
  - `webp`, `gradient.png`: the lossless WebP went from 1.23 kB to 152 bytes.
  - `webp`, `gradient-16bit.png`: a near-lossless WebP at level 60 (15.9 kB) became a lossless WebP of 710 bytes.
  - `webp`, `icon-6x6.png`: the lossless WebP went from 72 to 54 bytes, and so did the suite's.
  - `suite`, `gradient.png`: the WebP went from 1.23 kB to 152 bytes, and the AVIF (659 bytes), now larger than it, was dropped.
  - `suite`, `gradient-16bit.png`: the near-lossless WebP (15.9 kB) became a lossless WebP of 710 bytes, and the AVIF (15.0 kB), now larger than it, was dropped.
  - `same` and `webp`, `lossless.webp`: the lossless WebP went from 2,810 to 2,824 bytes, the one fixture where the harder setting is larger.
- `wio` no longer writes `<picture>` markup, since it optimises images and leaves how a page shows them to the page: `--markup` and `FileResult`'s `markup` field are gone. `schemaVersion` stays 1, as the field was never released.
- `--max-width <px>` (`maxWidth` in the run's `options`) shrinks a raster image wider than the cap to that width, keeping its aspect ratio, before the quality search, and every output scores against the shrunk pixels. A shrunk image has no strip, so it falls back to a re-encode in its own format, and is kept with the new warning `W_NOT_RESIZED` when nothing at the new width is smaller. Each output now has its own `width` and `height`. See `docs/modes.md`.
- Every raster output keeps the copyright, licence and AI-origin fields Google Images reads (Creator, Credit Line, Copyright Notice, Web Statement of Rights, Licensor URL and Digital Source Type) as one compact XMP packet, whatever format it is in. They're read from the input's XMP, then its IPTC, then EXIF's Artist and Copyright, then PNG's Author and Copyright text. Each output reports them in `rights`, and the run's `options` gain `stripAll`, which removes them too, and `rights`, which adds the fields a file lacks (listed in each output's `rightsAdded`). The packet counts in every size comparison: fields that would leave nothing smaller than the input are left out, with the new warning `W_RIGHTS_NOT_ADDED`, which also covers a small file whose own fields don't fit, so its other metadata still goes. A file whose outputs carry no licence field gets the new warning `W_NO_RIGHTS`. See `docs/modes.md`. It changed these decisions at target 80, the default then:
  - Every raster fixture without rights (`gradient.png`, `gradient-16bit.png`, `screenshot.png`, `logo-alpha.png`, `semi-transparent.png`, `icon-6x6.png`, `display-p3.jpg`, `exif.avif`, `photo-rhino.jpg` and `photo-sunset.jpg`) gains `W_NO_RIGHTS` in every mode.
  - The fixtures with a Creator (`text-chunks.png`, `orientation-6.jpg`, `lossy.webp`, `lossless.webp` and `rotated-xmp.avif`) and those with a Creator and Copyright Notice (`photo-butterfly.jpg` and `photo-night-bridge.jpg`) keep them, so every output grows by the packet: 370 to 590 bytes, with the same method and quality. `rights.jpg` keeps all six fields, and grows by 1.13 to 1.19 kB.
  - `same` and `webp`, `lossless.webp`: the lossless WebP (2,824 bytes) became the strip (3,198 bytes), which carries the Creator in fewer bytes, since the re-encode would also need a `VP8X` chunk.
- The command line's rights flags: `--strip-all` removes every metadata field, the rights included, and `--creator`, `--credit`, `--copyright`, `--rights-url` and `--licensor-url` add the fields a file lacks. `--strip-all` with any of the others, an empty value, or a URL that isn't `http:` or `https:` is a usage error. `W_NO_RIGHTS`'s message names them, and the table gives it once for the run rather than on every file, while `--json` and `--ndjson` keep it per file. `wio --help` has a Metadata section saying briefly what is kept and what is removed.
- `wio --help` says what each option does and its default, and has short Modes, Targets, Outputs and Inputs sections. `wio compare --help` lists the verdicts and the score each starts at. Every help page fits 80 columns, in a terminal or piped.
- When the reader of its output goes, such as `head` in `wio photos --ndjson | head -5`, `wio` stops the run as Ctrl+C would and exits 141, where it crashed with an `EPIPE` error. `wio --help | head` just prints less.
- A desktop app, Web Image Optimiser, for comparing outputs before saving them. Open images with Browse, by dropping them on the window or from File, then Open..., and each runs in `suite` mode at the `web` target straight away, into a temp folder the app removes when it quits, one batch at a time. One image opens its comparison grid; several are listed beside it with their progress, savings and the batch's totals. Each image's warnings and errors show with it. See `docs/desktop.md`.
- The app's comparison grid shows the original beside its AVIF, WebP and fallback, zoomed and panned together (fit, 100% at one image pixel per screen pixel, 200%, 400%, or the scroll wheel), with one output wiped against the original and a diff overlay with its opacity.
- Each output pane's target-score slider, from 50 to 100 in steps of 5 with the presets marked, searches its format for the smallest output that reaches the new target, reusing every quality the image's earlier searches tried. The grid marks the panes the suite's chain rule leaves out, so what Save suite saves is visible.
- Saving: a pane's Save opens the OS's save dialog in the original's folder, with the output named as `wio` names it, or the next free name as the OS names a copy (`photo (1).webp` on Windows, `photo 2.webp` on macOS), and replaces a file, the original included, only once the dialog has confirmed it. Save suite and Save all (also in the File menu) save the outputs each suite keeps into a folder, never replacing a file. Nothing larger than its original is saved.
- The app's options bar has the command line's `--max-width`, `--strip-all` and rights flags, as Max width, Remove all metadata and Rights info, and remembers them, with the folder images were last opened from. A change to the metadata options rewrites the outputs shown without a new search. Help says what's kept and what's removed, in `wio --help`'s words, and About shows the versions of wio, sharp and libvips.
- Unsigned installers: a per-user installer for Windows, and a `.dmg` for each Mac architecture. They add the app to the OS's Open with menu for PNG, JPEG, WebP, AVIF and SVG, without making it the default for any of them, and images dropped on its shortcut, `.exe` or Dock icon open in it. `docs/desktop.md` says how to open an unsigned app.
- The default target is `web` (70, differences barely noticeable side by side) rather than `high` (80), in the command line as in the desktop app, for smaller files. `--target high` gives the old default. `W_NOTICEABLE` now marks an output below 70 rather than 80, so a run at the default gets it only when a conversion can't reach the target. Every lossy output is smaller, 29% over every fixture in every mode, and these decisions changed:
  - `same`, `display-p3.jpg`: the original, kept with `W_ICC_KEPT` (6.50 kB), became a JPEG at quality 74 (4.05 kB), without the warning.
  - `webp`, `exif.avif` and `rotated-xmp.avif`: the AVIF's strip, with `W_NOT_CONVERTED`, became a WebP (15.7 kB and 14.9 kB).
  - `avif`, `lossy.webp`: the WebP's strip, with `W_NOT_CONVERTED`, became an AVIF at quality 55 (17.5 kB).
  - `suite`, `orientation-6.jpg`, `photo-butterfly.jpg` and `rights.jpg`: each gained a WebP, now smaller than its JPEG fallback.
  - `suite`, `exif.avif` and `rotated-xmp.avif`: each gained a JPEG fallback beside its AVIF.
  - `suite`, `lossy.webp`: the lone WebP became an AVIF (17.5 kB) and a JPEG fallback (21.0 kB). The WebP, now 21.1 kB, is dropped as larger than the fallback.
  - `suite`, `text-chunks.png`: the WebP (11.5 kB) was dropped, now larger than the JPEG fallback (11.1 kB).
- `--concurrency` is how many quality scores run at once, rather than how many files. A run of at least that many files is unchanged, one file per score. A run of fewer shares them out, so each file scores its candidates side by side on threads of its own, with the same outputs: a `suite` run of one 12 MP photo took 373 s rather than 464 s on a 20-thread machine. The desktop app's runs share them out the same way, and its target searches score on threads of their own.
- A quality search with scoring threads to spare also tries the qualities it may need next while it waits for the one it needs, and keeps only the attempts it would have made one at a time, so the outputs are the same. A `suite` run of one 12 MP photo now takes 194 s rather than 373 s on a 20-thread machine, and a desktop app slider's WebP search of it about half the time it did.
- A process that runs several scores at once also gets more threads for sharp's encodes and decodes, half as many again as its scores, so the qualities a search tries ahead of need don't hold up the one it needs, with the same outputs. On a 20-thread machine, a `suite` run of one 12 MP photo took 167 s rather than 209 s, and a desktop app slider's WebP search of it 57 s rather than 75 s.
- The desktop app's scoring threads end once they've been idle for 30 s, freeing the memory they hold, about 2 GB each after a 12 MP image, where they kept it until the app quit. A search after that starts them again, which costs about 15% of one score.
